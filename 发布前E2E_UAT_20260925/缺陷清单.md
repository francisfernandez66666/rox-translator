## F-03 【P1】重复发码复用已消费的 Turnstile token → 403「人机验证失败，请重试」死循环

- **现象（字节级）**：第二次点「发送验证码」，请求携带与第一次**完全相同**的 token（前缀 `1.UBJd_35L4q7V4BT0L…`，两次逐字一致），响应 HTTP 403 `{"message":"人机验证失败，请重试","success":false}`。
- **源码根因**：`takeCaptchaToken()` 取走 token 后调 `reexecTurnstile()` 重挂组件，但实测重挂后 widget 回调写回的是**同一个缓存 token**（Turnstile re-execute 在未过期窗口内可回发相同 token）；后端 `siteverify` 对已消费 token 判失败。前端无 reset 兜底，用户侧表现为「点一次说人机验证失败」且反复如此。
- **误导面**：真实原因是 token 复用，但文案把用户指向"再验证一次"，而页面上根本没有可再操作的验证框。
- **修法前置**：失败分支应调 `turnstile.reset()` 强制领新 token（或禁用重发按钮 60s 对齐后端冷却）。

## F-04 【P1】邮件异步队列「入队即成功」+ 重试 5 次后静默丢弃：发信彻底失败时接口仍回 200 success:true，全链路无告警

- **现象（字节级）**：SMTP 拨号必然失败（见 F-01 根因链）的情况下，`POST /api/auth/email-code` 仍返回 HTTP 200 `{"success":true,"noop":false,"message":"验证码已发送，请查收邮箱"}`；服务端日志里 5 次即时重试后无任何升级动作（不降级提示、不计失败指标、不告警）。

- **修法前置（不改代码，仅登记）**：a) 发码接口在 SMTP 未就绪时应有健康预检（或至少 Noop/失败口径真实）；b) 队列死信应落日志告警位 + 管理台可见；c) 可考虑重要邮件（重置密码/注册码）同步发送或短等待回执。

- **现象（字节级，10:29-10:31）**：翻译扣 18 积分后，顶栏持续显示「余额 1,100 积分 ≈ 660 句 / 今日已耗 0 积分」；`GET /api/me/package` 实际已是 `points_balance:1182, points_used_today:18`；整页刷新后顶栏才更新为「1,182 ≈ 709 / 已耗 18」。
- **补充**：1,100→1,200 差额已查明**不是缺陷**——每日登录 +100、每周发起翻译 +100 临时积分任务（个人中心页可见「已自动发放」），首屏时后一笔尚未入账。
- **修法前置**：done 帧/扣费回调后重拉 `me/package` 或按 done 帧 `points_used` 就地更新顶栏。

## F-12 【P2】定价页充值包标价与收银台实际应收不一致：¥299/3,000 积分 vs 下单应收 ¥269.10

- **现象（字节级）**：`/pricing` 宣示「充值包·小 3,000 积分 ¥299」；管理台在线充值 3,000 积分 → `pay/create` 回 `amount_money:269.1`（=299×0.9，页面文案称「按平台积分尺子价计」）。两个口径同时在给钱看，客户会按定价页理解成交价。
- **修法前置**：产品定一个真值（尺子价或套餐价），另一处改文案对齐；首月 5 折只作用订阅口径的话也要在页面上说清。

## F-13 【P2】管理台「选购套餐」两档均「暂无可订阅套餐」：对外承诺的包月订阅/充值包没有自助购买货架

- **现象**：计费与套餐页「包月订阅（t+30 滚动额度）」与「充值包（永久有效）」列表均为空，仅有下方自由数额的「在线充值」可下单；而 `/pricing` 明码宣传 4 档。新客想按套餐购买无从下手。
- **修法前置**：确认是货架数据没配（后台套餐/商品表为空）还是可见性过滤把它滤掉；发布前必须把定价页承诺的档位上柜。

## F-14 【P3】用量台账时间列显示 UTC（02:38），与全站的本地时间（10:38）差 8 小时；「模式」列在工单行显示「快速/-」与实际选择关系不直观

## F-15 【P3 · 译员质量观察，交决策】专业校对模式把「单笔满300减50」译成「purchases over **R**300 … **R**50 off」——人民币被写成兰特的货币符号
