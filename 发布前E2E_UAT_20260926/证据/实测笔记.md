### F-44（新登记·严重·客户可感知）对照编辑保存＝假成功，修订与审批全部丢失

- 现象：① UI 编辑→保存 → `POST /api/tickets/segments/save?id=92&lang=en` → **200 `{"saved":1,"success":true}`**，随后 `GET /api/tickets/segments?id=92&lang=en` 回来 `edited_text:"" / status:"" / note:""`，审批下拉回显「待处理」；② 绕开 UI 以**真实差异报文**直连接口（`{"edits":[{"index":0,"edited_text":"API-LEVEL-PROBE edited translation 11.11 CNY 299.","status":"approved","note":"uat-note"}]}`）→ 同样 `{saved:1}`、同样读回全空 ⇒ 与前端/脚本手法无关；③ 交付侧连带失真：工单 92 的下载产物 `xl/sharedStrings.xml`（403B 解包）里仍是机翻原文「…on Double Eleven…」，**不含任何修订串**；④ 历史面全灭：09-25 曾判 PASS 的工单 76（当时保存过审批+编辑）、文件工单 84，本轮读回 `非空编辑段数=0` ⇒ 生产库中既有全部在线修订均不可见。
- 根因（代码级，未改一行）：写侧 `UpsertTranslationEdit` 走方言层 `db.Exec(s.db, db.CurrentDialect(), q, …)`（`internal/store/edits.go:53`）⇒ PG 下占位符被正确改写、INSERT…ON CONFLICT 成功；读侧 `GetTranslationEdits` 用**裸连接** `s.db.Query(...)` 且 SQL 里写 `WHERE ticket_id=? AND lang=?`（`internal/store/edits.go:59-61`）——绕过 `db.RewritePlaceholders`（`internal/db/query.go` 的 `?→$n`），PostgreSQL 直接语法错；调用方 `edits, _ := s.Store.GetTranslationEdits(id, lang)`（`internal/api/editor.go:95`）把错误吞掉 ⇒ 永远空。同文件 `ListKBTerms`（:93）同型裸 `?` ⇒ 线上 segments 响应 `"terms":null`（术语高亮同一条腿）。这正是 AGENTS §一·4「所有 SQL 必须同时支持 SQLite/PG、必须走 db.CurrentDialect 分支」点名的历史高频踩坑。
- 为什么单测没抓到：SQLite 认 `?`，本地/CI 快跑（`DB_DRIVER=sqlite`）读得到；PG 方言只在 run_uat 矩阵里跑，而矩阵未覆盖「保存后读回」这条断言（09-25 只断 `{saved:n}`，属假绿）。
- 修法前置（供决策，本轮不动代码）：`GetTranslationEdits`/`ListKBTerms` 改走 `db.Query(s.db, db.CurrentDialect(), …)`；并把断言补成「save 后 GET 必须等值回显 + 交付产物含修订串」，且**必须在 PG 方言下跑**（AGENTS §一·7 末条）。
- 商业影响：对照编辑是顶栏三大 Tab 之一、也是审批工作流与「术语逐条对照」演示卖点；现在客户改完点保存看到「已保存 1 段」，实际什么都没留下，下载/交付仍是机翻稿 —— 发布前两天属**必须在 P0 队列**的一条。
