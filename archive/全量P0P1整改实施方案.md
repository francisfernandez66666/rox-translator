## 一、P0-1 JWT 密钥硬化（auth.go）

**现状**：`var jwtSecret = "trans-platform-jwt-secret-2026"`，`init()` 仅当 `JWT_SECRET` 非空才覆盖。若部署漏配（且未开 `REQUIRE_PROD_SECRETS=1`），任何人可用该常量伪造 super_admin。

**改动**：
1. 默认值改为空串 `var jwtSecret string`。
2. `init()`：若 `JWT_SECRET` 为空，用 `crypto/rand` 生成 32 字节随机串作为进程级密钥，并 `log.Printf` 告警"JWT_SECRET 未设置，已生成随机密钥（重启/多副本将失效，生产必须设置）"。
3. `RandomSecret()` 回退逻辑保留（仍指向 jwtSecret，但此时已非已知常量）。
4. `Verify`/`Sign` 不变（仍用包级 jwtSecret）。
5. 校验：`REQUIRE_PROD_SECRETS=1` 路径在 `main.go` 已 Fatalf，无需改；补齐注释说明随机密钥仅本地开发语义。

**风险**：随机密钥下重启会令旧 token 失效——这正是期望行为（替代"可伪造常量"）。多副本需共享 JWT_SECRET，文档已在部署指南强调。

## 二、P0-2 计量影子账本自愈（sink.go）

**现状**：`Record()` 仅首次 seed 影子余额（`shadowOk` 永不再 seed）；flush 失败（`ErrInsufficientBalance`）时影子已被乐观扣减且**永不回读**，导致该租户此后所有任务首次 LLM 调用即 `Abort()`，即使后续充值也不恢复，直到进程重启。

**改动**：在 `flush()` 内，对每个租户分组在开始扣减前**重新读取 `TenantRemainTotal` 回写 shadow**（一次/周期/租户，符合"每周期每租户一次 DB 读"的批处理目标，不破坏性能优化）。逻辑：
- `flush` 取 `groups` 后，对每个 `tid`：`g,p,err := Store.TenantRemainTotal(tid)`；成功则 `s.shadow[tid]=g+p; s.shadowOk[tid]=true`。
- 随后按 `sum(batch.Quantity)` 判断是否够扣：不足则对该批逐条 `Abort()` 且不计入（DB 不变）；足够则 `RecordUsageBatch`。
- `Record()` 的即时中止保留（乐观检查），但其使用的影子会在下一轮 flush 被回读纠正，杜绝"永久负化"。
- 充值时 `balance_accounts` 变化会在此后首个 flush 周期被回读感知，租户自动解冻。

**验证**：单测场景——tenant A 余额耗尽 → 任务被中止 → 模拟充值（直接写库）→ 下一周期 flush 后新任务不再被中止。

## 三、P0-3 语义 KB 检索按真实租户生效（engine.go + kb/db.go）

**现状**：向量索引全局构建，但 `IDLangs` 映射由 `db.AllRowLangs(0)` 填充（仅超管 tenant 0 行），`ScopedSearchScope`（`npz.go:568`）在 `wantLangs` 非空时丢弃所有 `IDLangs` 缺失的行 → 真实租户请求目标语言时候选全被丢，语义检索形同失效。

**改动**：
1. `NewEngine` 与 `LoadNPZ` 重建索引路径中，`IDLangs` 改为基于**全租户** `AllRowLangs(-1)`（新增/复用"忽略 tenant 过滤"的查询）或在 `AllRowLangs` 支持 `tenantID<=0` 返回所有租户行。
2. `ScopedSearchScope` 的租户隔离改由 `ScopedSearch(...)` 调用方传入的 `tenantID`/`packIDs` 完成（已存在按包/租户过滤逻辑），而非依赖 `IDLangs` 是否包含该行。
3. 保留"租户1共享包对全体可见"的 `sharedFilterSQL` 语义不变。
4. 复用现有单测 `TestVectorScoped*` 验证。

## 四、P0-4 租户删除级联 + 索引（tenant.go + store.go）

**改动**：
1. `tenant.Delete` 增补：删除 `tm_segments`（独立 .sqlite，需持 `kb.Open` 的 RawDB 句柄或新增 `kb.DB.DeleteTenant(tid)` 方法）、`usage_daily`、`audit_logs`、`notifications`、`feedbacks`、`alerts`、`jobs`、`system_config` 中该租户行。
2. 新增 `kb` 包 `DeleteTenantSegments(tid)` 并在 `tenant.Delete` 内调用（需在主库事务外单独处理跨库，或在 `kb.Open` 暴露 DeleteTenant）。
3. 索引：`CREATE INDEX IF NOT EXISTS idx_ticket_state_ticket ON ticket_state(ticket_id)`；`tm_segments(zh_hash)` 已有唯一索引，补 `idx_tm_zh ON tm_segments(zh)` 供 `LIKE` 模糊（注意：LIKE 前缀仍全扫，仅作覆盖说明）。
4. 评估：SQLite `PRAGMA foreign_keys=ON` 默认关闭，应用层级联优先，本批以应用层清理为主，不强行改 FK（避免连锁迁移风险）。

## 五、P1 批（详见各文件 diff）

- **P1-1** `GetTicketFile` 增加 `tenant_id` 参数或调用点二次校验（OpenAPI download / ticket detail）。
- **P1-2** `/metrics` 未设 `METRICS_TOKEN` 时返回 401；`pay.go` `X-Admin-Token` 比对改 `crypto/subtle.ConstantTimeCompare`。
- **P1-3** markup：删 `billing.go:240` 仓库层对 quantity 的二次乘 `rate_card` 倍率（cost=quantity 单一口径）；`engine.go:1737` KB 重建改走 `billing.RecordUsage`（sink）。
- **退款口径（按「费用一律 token 口径、句数不参与计算」原则重做）**：`CreatePackageOrder` 下单时一次性把 `pkg.Sentences×折算率` 折算为 token 数写入 `orders.amount_tokens`（此前为 0）；`MarkOrderPaid` 发放与 `RefundOrder` 核算均直接采用该 token 数，删除原 `sentences*sentenceRate` 运行期重算；新增 `PackageOrderTokenBackfill` 迁移补全存量包订单的 `amount_tokens`；发放路径保留一处兜底（tokens==0 时回退句数折算，仅保护未迁移历史单）。
- **入账/扣费同单位（按「入账也按 markup 倍数、倍率后台可配」原则）**：新增 `Store.MarkupMultiplier()`（读 `billing_markup_multiplier`，默认 1.5、强制 ≥1.0，与扣费侧 `Server.markupMultiplier` 同源同键）；`CreatePackageOrder` 把「句数×折算率×MarkupMultiplier」一次性写入 `amount_tokens`，`MarkOrderPaid` 兜底亦乘 MarkupMultiplier → 入账 token 与扣费 token（`usage_ledger.quantity = 真实消耗 × markup`）单位完全一致，「1 入账 token = 1 扣费 token」；markup 倍率经后台 `admin_packages.go` 接口可实时调整。存量已支付包订单的 `PackageOrderTokenBackfill` 维持旧口径（句数×折算率、不含 markup）以与其实际已入账余额自洽、退款不超收；新建订单起一律含 markup。
- **前端「套餐/定价管理」配置项（markup 倍率）**：后端 `handleAdminPackageSettings`/`handleAdminPackageSettingsSave` 已支持读写 `billing_markup_multiplier`；前端 `panels_c.tsx` 原「运营参数（超管）」弹窗内容已**移至主面板常驻小节**（与 `estimate_tokens_per_sentence`、`trial_sentences`、强制计费开关、支付模式并列，超管可见），并补强：非法值（<1.0）由静默 return 改为 `packages.markupInvalid` 告警提示、新增 `packages.markupHint` 说明全局生效范围、i18n 中英补全。
- **P1-4** `deriveAEADKey`：`JWT_SECRET` 缺失时随机派生（基于进程随机盐）并告警，不再用 `SHA256("|rox-apikey-enc")` 常量。
