## 〇、架构总体判断

**形态**：单 Go 二进制（SQLite 单库 + npz 向量索引）+ React/TDesign 前端 + systemd/Caddy。
内部包划分清晰：`api / engine / orchestrator / store / billing / kb / fileproc / llm / tenant / iam / gate / culture / qa / evals`。

**做对了的部分（已逐条代码核对，非文档自夸）**
- 鉴权/租户隔离模型扎实：JWT 随机密钥、跨租户写操作 SQL 层强制 `tenant_id`、`API Key` 用 `crypto/rand` 160bit + AES-GCM、`tm_segments` 路径的 `ScopedSearchScope` 继承链/兄弟隔离实现正确。
- 性能优化到位（1G 内存红线）：`GOMEMLIMIT`、`usage_daily` 计数器替代逐请求 LIKE 全扫、实时计量批量落库消除 `SQLITE_BUSY`、`FILEPROC` 子进程 OOM 优先受害者 + 超时杀进程组。
- 并发/资损修复经得起核对：C4 已批准重跑保护、取消-认领竞态守卫、`RequeueStalledTickets` 删「不看租约年龄」释放段、双桶台账 `DeductWithGrants` 事务原子、退款/订单幂等——均真实落地。
- **实时计费已接通**：`main.go:249` 挂载 `eng.LLM.OnUsage = srv.ChargeUsageRealtime`；`llm/client.go:512,626` 每次 chat/embed 触发；`stream.go:120` 经 `userOrgCtx(r)` 继承 `withTenant` 中间件注入的租户，链路完整，计费真实生效。

**结构性弱点**
- `store` 巨型 god-object（billing/KB/工单/组织/审计/配额全堆一起）。
- SQLite 单写者 + `_txlock=immediate`：**单机红线**，无水平扩展路线图；高并发下读写串行至单一 5s busy_timeout。
- **质量闸门（gate/culture）是孤儿**：只挂在 orchestrator 的 `pro` 工作流上，对主路径（即时翻译/文件翻译）完全不生效。
- KB 双模型分裂：`tm_segments`（检索/隔离正确）与 `kb_entries`（业务/未隔离）并存，隔离逻辑只贴在前者。

## 三、待设计落地的核心项（R1/R2）

### R1 质量闸门上主路径
当前 `gate.Run`（8 项硬校验）与 `culture.Run`（语言文化包输出闸）仅在 `orchestrator` 的 `pro` 工作流 `runGate`/`runCultureGate` 调用。
即时翻译（`HandleText`）与文件翻译（`HandleFile`）输出后**未做任何约束校验**。
**设计**：在 `HandleText`/`HandleFile` 返回最终译文前，新增 `applyOutputGates(ctx, source, translations)`：
- 逐语言跑 `gate.Run`；不通过时若非 fast 模式则带错误意见触发一次 `TranslateWithFeedback` 重试，仍失败则标记该语言失败（不静默丢弃）；
- 逐语言跑 `culture.Run`（含共享租户1安全句）；命中安全句按 `locale_gate_enforced` 决定是否 reject。
- fast 模式仅做轻量 L1 提示词（保持「译出为止」语义），不阻断。

### R2 KB 跨部门隔离
`kb_entries` 当前经 `kb_packages.pack_type` 区分租户/行业/部门，但 `FindEntriesBySource`（`kbpackages.go:384`）**只按 `tenant_id+role='source'` 返回全部部门包**。
**设计**：
- 给 `kb_packages`/`kb_entries` 增加组织可见性归属（org_id / dept_id 可见范围）；
- 新增 `FindEntriesBySourceScoped(tid, orgID, srcLang, srcText, scope)`，仅返回调用方可见包；
- `runKBMatch` 改用 scoped 查找（工单带 org_id 时按组织可见性过滤），未带 org 时回退租户级不跨部。
- 同步补 `FindEntriesBySourceScoped` 的单测（当前该路径零覆盖，是泄漏未被发现的根因）。
